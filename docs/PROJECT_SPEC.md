# Project spec — injectlens

- **Name:** injectlens
- **Category:** llm-security
- **Target user:** a developer who feeds documents (markdown/HTML/email-like text) into an LLM pipeline and wants to know, offline and before ingestion, whether those documents carry indirect prompt-injection payloads.
- **Problem:** indirect prompt injection hides instructions in places humans do not read — zero-width characters, Unicode tag characters, base64 blobs, white-on-white HTML — so manual review misses it and cloud "AI scanners" require uploading the very documents you are worried about.
- **Solution:** a standard-library-only CLI that normalizes each line (HTML entities → base64 side-channel decode → Unicode tag decode → invisible-character strip), matches 12 documented rules (IL-001..IL-012) against the normalized text plus decoded payloads, prints per-file findings with gist-section references, and offers a `clean` subcommand that converts hidden content back into visible text for review.
- **Core workflow:** `scan` a directory → read the per-file findings → `clean` the offending files → re-scan to confirm.
- **Must-have features:** full normalization pipeline as pure functions; 12 rules with stable ids, severities (info..critical) and MITRE/gist references; base64 blob decoding with a false-positive guard; structural hidden-unicode detection (IL-007); text + JSON reports; `--min-severity` display filter and `--fail-on` gate; `clean` subcommand; exit codes 0/1/2.
- **Nice-to-have features (not in 0.1.0):** YAML front-matter aware scanning, HTML tag-stripping before rule matching, rule packs per document type (email vs markdown vs HTML), suppression files.
- **Stack:** Python 3.10+ standard library only; unittest; no third-party dependencies; no network access at runtime.
- **Test strategy:** 68 unittest cases over the normalization stages (including U+E0041 → 'A' decoding and the base64 FP guard), metadata completeness, a positive and negative case for every rule, corpus integration (all 12 rules fire, benign fixture stays clean), and CLI exit codes/JSON shape/clean output.
- **Demo/result strategy:** a six-file defanged corpus under `examples/corpus/` generated by `examples/generate_fixtures.py`; scan reports, clean outputs and the full test log captured under `results/`.
- **Safety considerations:** scans only the local files you point it at; all example payloads are defanged structural skeletons with fake targets ("print the word BANANA"); nothing executes. See SECURITY.md.
- **Definition of done:** all tests green, demo commands verified, corpus covers every rule, docs and RESULTS.md match observed behavior.
